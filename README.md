# 毫秒定时点击（ClickTimer）

一个体积极小的 Android 单点定时点击工具：保存多个时间点作为预设，选中其中一个后，在悬浮准星位置按毫秒级精度自动点击一次。

- 包名：`com.mclick.timer`
- 当前版本：`1.4`（versionCode 5）
- 最低系统：Android 7.0（API 24），targetSdk 34
- 安装包：约 **46 KB**
- 依赖：**零第三方库**，纯原生 Java + Android 系统 API，不使用 Gradle / AndroidX
- 无网络权限，不读取屏幕内容

## 功能

- **多个时间预设**：时、分、秒、毫秒保存到列表，最多 30 个；点选一项高亮，右侧可删除。
- **单点执行**：多个时间只是方便选择，启动后只执行选中的那一个。
- **米秒级设定**：时、分、秒为自绘大字号滚轮（系统闹钟式上下滚动、自动吸附），毫秒为数字输入框。
- **悬浮准星定位**：`TYPE_ACCESSIBILITY_OVERLAY` 悬浮窗，拖动到目标位置即可，无需“显示在其他应用上层”权限。
- **倒计时固定显示**：倒数时间固定在屏幕顶部中间，不跟着准星移动，也不拦截触摸。
- **启动 / 结束回撤**：启动后按钮变为「结束任务」，点一下即可撤销误触；执行完成或结束任务后恢复为「启动选中时间」。
- **不启动不执行**：仅显示悬浮按钮不会触发点击。
- **省电**：空闲时完全停止轮询；等待期间倒计时自适应刷新。
- **无后台常驻**：不跑前台服务、不持唤醒锁、不申请通知权限；划掉界面不影响已启动的短时任务。

## 使用步骤

1. 打开应用，点状态按钮或「去开启无障碍」，在系统设置中开启「毫秒定时点击」的无障碍服务。
2. 拨好时、分、秒并填写毫秒，点「保存到时间列表」（可保存多个）。
3. 点一下列表里要执行的时间，选中项高亮。
4. 点「显示悬浮按钮」，把准星拖到需要点击的位置。
5. 点「启动选中时间」。到点后会在准星中心自动点击一次。
6. 若启动错了，点「结束任务」立即回撤；「隐藏悬浮按钮」会停止并隐藏。

时间按当天最近的一次执行；若今天已过，会顺延到明天。

## 精度说明

- 以墙钟时间计算目标，再换算到 `elapsedRealtimeNanos` 做绝对时间对齐。
- 先粗睡，最后约 0.4 ms 自旋等待，避免线程唤醒抖动。
- 点击前约 250 ms 临时移除悬浮窗，防止准星挡住注入的点击。
- 注入手势时长 24 ms。
- 系统注入点击本身通常有几十毫秒延迟，可用「延迟补偿」提前执行来抵消：实测偏晚多少毫秒就填多少。
- 建议使用期间保持屏幕常亮；系统深度休眠/省电策略可能影响最终触发时刻。

## 省电与后台

- 准星倒计时自适应刷新：5 分钟以上每 5 秒，1 分钟以上每 1 秒，10 秒内每 500 ms，最后 10 秒逐步提速到 50 ms。
- 应用前台状态也不再固定 100 ms 轮询：只在等待执行时刷新，空闲时没有定时器。
- 不运行前台服务，执行结束后任务本身不再占用 CPU。

## 权限与隐私

- 无障碍服务：注入点击与显示悬浮准星，需要在系统设置中手动开启。
- 不申请网络、存储、位置、通知、前台服务等权限。
- 所有数据（时间列表、选中项、准星坐标、补偿值）只保存在本地 `SharedPreferences`。

## 构建

环境要求：

- JDK 17（`build.sh` 优先使用本机 JDK 17，否则使用 `javac`）
- Android SDK：`platforms;android-34`、`build-tools;34.0.0`
- 不需要 Gradle

```bash
cd ClickTimer
./build.sh
# 产物：ClickTimer.apk
```

自定义 SDK 路径：

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk ./build.sh
```

版本号在 `build.sh` 的 `--version-code` / `--version-name` 中维护。

### 签名

- 签名文件：`signing/release.jks`，alias `click`，store/key 口令均为 `clicktimer`。
- 首次构建若文件不存在会自动生成；CI 与本地使用同一文件即可覆盖安装。
- **如果仓库公开，请不要提交签名文件**，改用 GitHub Secrets：`KEYSTORE_BASE64`（密钥文件的 Base64），工作流会自动还原。口令需与 `build.sh` 一致，或同步修改脚本。

## 我的习惯（持续记录）

### 使用习惯

1. 多个时间只是**预设列表**，一次只执行选中的一个，不做批量多点调度。
2. 固定流程：点选时间 → 显示悬浮按钮并拖到目标位置 → 启动；**不点启动绝不执行**。
3. 误触后用「结束任务」一键回撤；不需要额外的“停止执行 / 重新启动”按钮，按钮也不要频繁改文案。
4. 时、分、秒要像系统闹钟一样用滚轮拨动，滚轮数字必须够大、一眼看清；毫秒用输入框。
5. 列表项点一下即选中，同时同步到滚轮，方便查看和微调；删除放在列表项右侧。
6. 使用环境：**小米/红米（MIUI / HyperOS），不 root，也不接受 root / Shizuku 方案**。
7. 最大的痛点是“一键清理后无障碍被关闭、要重新勾选”；优先用系统白名单、自启动、后台锁定来避免，重开时希望尽量少点几步。
8. 后台被清理优先通过“授予自启动权限 / 不限制耗电”解决；自启动只是权限，应用是一次性任务、不会真的自启，目的是防止被杀后无障碍授权要重来一次。不主动强行停止应用。

### 开发约定

1. 零第三方依赖、无 Gradle/AndroidX，优先原生 Java 与系统 API。
2. APK 尽量小，当前约 41 KB；新增功能不引入大体积资源或库。
3. 中文界面，暖米色 + 新拟物风格，强调色为低饱和绿色。
4. 空闲状态不轮询、不持锁；只在等待执行时做必要刷新。
5. 构建走 `build.sh`，CI 与本地使用同一签名，保证可直接覆盖升级。
6. 版本号在 `build.sh` 维护；发布前更新 `versionCode` / `versionName`。
7. 不要手动“强行停止”应用：Android 会因此强制关闭无障碍服务，只能重新开启，任何应用都无法绕过。

## 小米 / HyperOS 设置（重要）

MIUI/HyperOS 的一键清理可能会强制停止应用，安卓随后会撤销无障碍授权。无 root 时无法让应用自行恢复，只能减少发生并缩短重开路径。

1. 设置 → 应用设置 → 应用管理 → 「毫秒定时点击」
   - 省电策略 → **无限制**
   - 自启动 → **允许**（仅授予权限；本应用是一次性任务、不会真的自启动，要权限只为防止被杀后无障碍授权被收回、又要重新来一次）
2. 最近任务：长按应用卡片 → **锁定**（部分 HyperOS 版本为按住卡片下滑锁定）。
3. 手机管家 → 清理加速 / 垃圾清理 → 右上角设置 → **清理白名单**，加入本应用。
4. 设置 → 无障碍 → 已下载的服务 → 「毫秒定时点击」→ 开启。
   - 若提示受限：应用信息 → **允许受限设置**。
5. 可选：设置 → 无障碍 → 无障碍快捷方式 → 选择本应用，之后可用双音量键快速开关无障碍。
6. 日常不要「强行停止」应用；清理时尽量使用白名单/锁定卡片。

说明：

- 从 1.4 起，状态按钮和「去开启无障碍」会直接跳到本服务的无障碍详情页，而不是无障碍总列表；MIUI 若不支持该跳转会自动回退到总列表。
- 即使完成以上设置，部分 MIUI/HyperOS 版本在一键清理时仍会撤销无障碍授权，这是系统策略，普通应用无法绕过；只能重开，或改用 root（本项目当前不采用）。

## 常见问题

- **开启无障碍时提示“受限制的设置”**：Android 13+ 需先在系统「应用信息」里允许受限设置，再回去开启。
- **到点没有点击**：确认无障碍仍开启；部分系统省电策略会限制后台，请在应用设置中授予自启动权限并设为不限制耗电。
- **点击偏晚**：填入「延迟补偿」，数值为实测偏晚的毫秒数。
- **划掉后台后无障碍被关闭**：优先检查是否使用了“强行停止”；日常用返回键退出或直接划掉即可，并授予自启动权限（仅为保住授权，应用不会自启）。
